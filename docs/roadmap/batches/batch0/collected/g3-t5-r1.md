## 3. 关键发现：P12 风险升级盲区

**任务定义标注 full 档（状态 schema 变更 + 兼容读取，含 migration 信号），
但轻任务入口未拒绝，按 standard 跑完。**

classify 的档位判定依据是路径 marker（auth/security/migration/concurrency/
artifact-protocol/shared-state/delete 关键词匹配 productPaths）：

- 实际 diff 路径：`harness/scripts/harness_fixback.py`、
  `harness/scripts/tests/test_harness_fixback.py`
- 路径中不含任何 full marker → signals=['production-code'] → standard

**根因**：路径启发式无法识别「schema 变更」语义——变更的是
`runtime/invalidations/` 回执的 schema（写入方在 harness_fixback.py），
但 diff 路径只显示 Python 文件名。migration marker 匹配的是路径中的
`migration`/`migrate`/`/sql/`/`.sql` 字样，与「JSON 回执加可选字段」
无路径交集。

**影响评估**：
- 产物质量无回退：26/26 测试绿、验收全过、兼容语义正确（旧 fixture
  读取不变实证）——本任务的 full 档要求（独立审查、恢复演练）在
  record-only 轻任务路径下本来就不执行，走完整流程也只是多一道评审。
- 但**风险升级有效性未达成**（提案 §10 批次 1 完成证据的第二项）：
  真正危险的 schema 变更（删字段、改语义）若以类似路径呈现，同样会
  漏判。T4 的备注（「涉及 artifact-protocol 邻接，若 classify 升档按
  升档后流程执行——这本身是测量点」）预示了同一测量需求。

**修复方向**（候选方案改进点，非阻断）：
1. 短期：任务入口接受显式 `--tier full` 声明（用户/上游知道任务是
   schema 变更时直接走完整流程，不依赖路径推断）；
2. 中期：classify 增加 schema 邻接路径规则（`runtime/`、`state/`、
   契约文件清单）作为 full 信号源；
3. 长期：diff 内容语义分析（识别 schemaVersion 字段变更）——成本高，
   需先证明路径规则的召回不足。
