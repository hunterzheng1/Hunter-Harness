## 3. 关键发现

### 3.1 P13（轻微）：归档 decision 事件的 tier 措辞误导

归档事件流出现 `decision | review missing on full tier (allowed by user)`，
但本任务 tier=standard。根因：`harness_task.py finish` 对轻任务归档固定传
`allow_missing_review=True`（harness_task.py:1387，轻任务流程无 review 阶段），
而 `harness_archive.py:8522` 的 note 文案硬编码 "full tier"——该文案在
standard 档下照常发出，读事件流的人会误以为发生了 full 档越权。

- 影响：仅事件流可读性（审计时需人工核对真实 tier）；无行为差异
  （standard 档本就不要求 review，`--allow-missing-review` 对它是空操作）。
- 修复方向：note 文案带上实际 tier（如 `review missing on {tier} tier`）或
  仅在 `risk_tier == "full"` 时发该 decision 事件。一行改动 + 事件断言更新。

### 3.2 T2 任务本身（观测点验证）

任务设计意图「区分目录不存在 vs 有 change 但分类失败」达成：实现者选择
`{"total": len(items), **{status: count}}` 的 dict 展开序（total 键在前，
不覆盖状态计数），并补了 INVALID-only 边界（全 INVALID 时 total=len 且
INVALID=len，调用方可识别异常态）。实现者未引入额外抽象（遵守禁止事项）。
