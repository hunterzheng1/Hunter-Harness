## 4. 新增发现

| # | 发现 | 类型 |
|---|---|---|
| P5 | **standard 档验证三连跑同一命令**：compile/unitTest/unitTestFull 三项全部解析为同一条 npm 链（build-profile 只有 unitTestFull 一个 target），等效同一验证跑 3 遍（679 s vs 单次 ~240 s）。候选方案应对 resolvedAs 相同的验证项去重 | 候选方案缺陷 |
| P6 | **验证粒度错配**：任务只改了 Python（harness_change.py），但 node 探测的 profile 只有 npm 链；g2 的 test_runner 能定向跑 Python 测试（46/46，~15 s）。候选方案缺「按变更语言/路径选验证」的机制 | 候选方案改进点 |
| P7 | **npm test 的 pretest 副作用**：`npm test` 触发 `pretest → sync:harness`，把 harness/ 源码（含候选脚本本身）同步进 bundle manifest，产生 hunter-workflow-family.json hash 变更——被正确识别为任务工作（非 foreign），但意味着「部署候选脚本」这个 env 动作会渗入任务提交 | 观察（试点方法学） |
| P8 | 任务规格说 events.ndjson 取 `createdAt`，但实际事件 schema 字段是 `timestamp`——按规格实现的 lastActivityAt 对真实 change 恒为 null。规格与 schema 的漂移是任务设计侧问题（g2 同样按规格实现，行为一致） | 任务规格问题 |
