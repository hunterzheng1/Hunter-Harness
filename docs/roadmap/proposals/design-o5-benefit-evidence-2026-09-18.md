### 3.3 执行规程

1. **冷暖缓存分开**：每格先跑 1 次冷缓存（新会话 + 新工作区），再跑 2 次暖缓存；冷/暖分别报告。
2. **防答案泄漏**：每次运行使用独立 clone 工作区与新会话；需求描述、起始代码、工具链、模型版本固定并记录。
3. **重复**：每格 ≥3 次（§11）；全部原始记录落盘 `batches/batch4/collected/`（命名 `<组>-<任务>-r<N>.md`）。
4. **记录口径**：端到端墙钟、流程维护时间（沿用 batch0 方法学 §4 口径：协调命令 + 仪式写作）、失败恢复次数与耗时、人工介入次数与内容、token（若 D5 可采集）。**产品缺陷造成的成本不扣除**，单独标注。

### 3.4 盲评与隐藏验收

- 每任务卡配**隐藏验收清单**（含失败路径、兼容性、用户修改保护三类检查），由 D4 盲评执行者持有。
- 实现会话只拿到任务卡，不拿验收清单；盲评结果独立落盘，与实现记录分离。
- 验收判定只由盲评给出，实现方的自报不计入。

### 3.5 版本冻结与缺陷处置

- 一次对照内三组版本全部冻结；发现缺陷需修复时：**保留该轮结果**（标注含缺陷），再用修复后新版本重建该格对照（§11）。
- 所有 SHA/版本号在执行记录中落盘。

### 3.6 判定与报告要求

- 报告分「初步试点」（批 A，每格 n=3）与「完整」（批 B 后）两版；样本不足处显式报告不确定性，不下普遍结论。
- 目标判定（§11，不得下调）：轻任务端到端中位时间 -20%、流程维护 -50%，以质量约束（盲评无新严重失败、无用户修改丢失）为前提。
- 未达标：继续诊断或明确报告未达标；禁止减少验收内容换取达标（提案 §10 同款约束）。
- token 不可测时标「未知」，并区分「测量工具已实现」与「收益已验证」；**禁止用行数或候选数量代替收益指标**。
